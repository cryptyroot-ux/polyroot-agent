## Core Concepts

### Separation of Concerns
PolyRoot enforces a strict separation between **Intelligence** (AI reasoning) and **Execution** (deterministic order submission). The AI proposes `TradeIntent` objects which contain no private keys or signing authority. The Executor validates, signs, and submits orders through a vault-backed signing path.

### TradeIntent Schema
```typescript
interface TradeIntent {
  marketId: string;
  outcomeId: string;
  side: "BUY" | "SELL";
  size: number;          // in base units (USDC = 1e6)
  maxPrice: number;      // probability 0–1, scaled 1e6
  orderType: "LIMIT" | "FOK" | "FAK" | "GTC" | "GTD";
  expiresAt?: number;    // Unix ms, required for GTD
  meta?: Record<string, unknown>;
}
```

### Modes of Operation
| Mode         | Financial I/O | Purpose |
|--------------|---------------|---------|
| `PAPER`      | No            | Full pipeline with simulated fills; default safe mode. |
| `SHADOW`     | No            | Live market data, simulated execution; validates reality gap. |
| `MICRO_LIVE` | Yes (capped)  | Real venue submission with explicit capital cap. |
| `LIVE`       | Yes           | Full live trading; requires Autonomy Charter sign-off. |

## Runtime Modes

### PAPER (Default)
- All venues run in simulated mode.
- Fills generated by paper fill simulator (`PR-VAL-04`).
- Metrics recorded, no network I/O to Polymarket.

### SHADOW
- Connects to live Polymarket order book via SDK.
- Executes through paper simulator.
- Requires `G4_SHADOW_MIN_DAYS` and `G4_SHADOW_MIN_CLUSTERS` evidence thresholds.

### MICRO_LIVE
- Real `VenueAdapter` submission to Polymarket.
- Enforces `G4_MICRO_LIVE_CAP_USD` (default 500 USDC).
- Requires injected `CryptoSigner` and `VenueAdapter` at bootstrap.

### LIVE
- Full production execution.
- Requires **Autonomy Charter** commissioning (out-of-band legal artifact).
- All G5 promotion gates must pass (`Phase 24 G5`).

**Transitions:**
```
PAPER → SHADOW → MICRO_LIVE → LIVE
```
Invalid transitions (e.g., `PAPER → LIVE`) are rejected at bootstrap.

## Configuration

All configuration is via environment variables (`.env`) or programmatic `RuntimeConfig`.

### Required Environment Variables

| Variable | Description | Required |
|----------|-------------|----------|
| `DATABASE_URL` | PostgreSQL connection string | Yes |
| `WALLET_PRIVATE_KEY` | Deposit wallet private key (0x-prefixed) | Yes (LIVE/MICRO) |
| `WALLET_ADDRESS` | Derived wallet address (0x-prefixed) | Yes (LIVE/MICRO) |
| `CHAIN_ID` | Polygon = 137 | Yes (LIVE/MICRO) |
| `RPC_URL` | Polygon RPC endpoint (HTTPS) | Yes (LIVE/MICRO) |
| `RUNTIME_MODE` | `PAPER` \| `SHADOW` \| `MICRO_LIVE` \| `LIVE` | No (default `PAPER`) |

### G4 Pipeline Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `G4_MICRO_LIVE_CAP_USD` | `500` | Max capital allocated in MICRO_LIVE (USDC). |
| `G4_MIN_EDGE_AFTER_COST` | `0.03` | Minimum probability edge after fees. |
| `G4_SHADOW_MIN_DAYS` | `30` | Minimum SHADOW baseline days before promotion. |
| `G4_SHADOW_MIN_CLUSTERS` | `100` | Minimum resolved clusters for SHADOW promotion. |
| `G4_REALITY_GAP_TOLERANCE_BPS` | `1000` | Max fill-rate gap (basis points) for promotion. |
| `G4_SLIPPAGE_BIAS_TOLERANCE` | `0.005` | Max signed slippage bias for promotion. |

### Observability Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `METRICS_PORT` | `9090` | Prometheus metrics endpoint port. |
| `HEALTH_PORT` | `8080` | Health check endpoint port. |
| `LOG_LEVEL` | `info` | `debug` \| `info` \| `warn` \| `error`. |

### Complete Example
```env
# Database
DATABASE_URL=postgresql://polyroot:secure_password@localhost:5432/polyroot

# Wallet (Deposit Wallet / Type 3 for Polymarket)
WALLET_PRIVATE_KEY=0xYOUR_PRIVATE_KEY_HERE
WALLET_ADDRESS=0xYOUR_WALLET_ADDRESS
CHAIN_ID=137

# RPC (Polygon Mainnet)
RPC_URL=https://polygon-mainnet.g.alchemy.com/v2/YOUR_KEY

# Runtime
NODE_ENV=production
LOG_LEVEL=info
RUNTIME_MODE=PAPER

# G4 Pipeline Config
G4_MICRO_LIVE_CAP_USD=500
G4_MIN_EDGE_AFTER_COST=0.03
G4_SHADOW_MIN_DAYS=30
G4_SHADOW_MIN_CLUSTERS=100

# Observability
METRICS_PORT=9090
HEALTH_PORT=8080
```

## Gateway API

The gateway exposes HTTP/JSON endpoints for control, monitoring, and introspection.

### Base URL
```
http://<host>:<port>   # default port 3000 for control, 8080 for health, 9090 for metrics
```

### Health & Readiness
| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/health` | GET | Public | Liveness probe — returns 200 if process alive. |
| `/ready` | GET | Public | Readiness probe — checks DB, RPC, venue connectivity. |
| `/metrics` | GET | Public | Prometheus metrics exposition (`METRICS_PORT`). |

### Runtime Control
| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/runtime/mode` | GET | Bearer | Current runtime mode and state. |
| `/runtime/mode` | POST | Bearer | Request mode transition (validates transition rules). |
| `/runtime/status` | GET | Bearer | Full status: mode, health, capital, positions, metrics. |

### Trade Intents (AI → Gateway)
| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/intents` | POST | Bearer | Submit a `TradeIntent` for validation and execution. |
| `/intents/:id` | GET | Bearer | Query intent status and fill details. |
| `/intents` | GET | Bearer | List recent intents with filters. |

### Positions & Portfolio
| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/positions` | GET | Bearer | Current positions across all markets. |
| `/portfolio` | GET | Bearer | Aggregated portfolio: capital, PnL, exposure. |

### Venue & Market Data
| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/venues` | GET | Bearer | Registered venues and their modes. |
| `/venues/:id/mode` | POST | Bearer | Set venue mode (`NORMAL`, `POST_ONLY`, etc.). |
| `/markets/:id/snapshot` | GET | Public | Current order book snapshot (yes/no prices, depth). |

### Authentication
- **Bearer Token** required for all non-public endpoints.
- Token configured via `GATEWAY_API_TOKEN` env var (min 32 chars).
- Clock-skew tolerant (≤ 30s).

## Executor Interface

The Executor is a deterministic, auditable component that signs and submits orders.

### VenueAdapter Capability Contract
Each venue implements `VenueAdapter` with the following capability surface:

```typescript
interface VenueAdapter {
  // Market data
  getOrderBook(marketId: string): Promise<OrderBookSnapshot>;
  getMarkets(): Promise<MarketInfo[]>;
  
  // Execution
  placeOrder(intent: TradeIntent, permit: Permit): Promise<OrderResult>;
  cancelOrder(orderId: string): Promise<CancelResult>;
  getOrderStatus(orderId: string): Promise<OrderStatus>;
  
  // Account
  getBalances(): Promise<TokenBalances>;
  getPositions(): Promise<Position[]>;
  
  // Venue mode
  getMode(): VenueMode;
  setMode(mode: VenueMode): Promise<void>;
  
  // Settlement
  getSettlementStatus(txHash: string): Promise<SettlementStatus>;
}
```

### Venue Modes
| Mode | Submit | Cancel | Read |
|------|--------|--------|------|
| `NORMAL` | ✅ | ✅ | ✅ |
| `POST_ONLY` | ✅ (post-only only) | ✅ | ✅ |
| `CANCEL_ONLY` | ❌ | ✅ | ✅ |
| `READ_ONLY` | ❌ | ❌ | ✅ |
| `UNAVAILABLE` | ❌ | ❌ | ❌ |
| `UNKNOWN` | ❌ | ❌ | ❌ |

### Signer Interface
```typescript
interface CryptoSigner {
  sign(payload: SignablePayload): Promise<Signature>;
  verify(payload: SignablePayload, signature: Signature): boolean;
  getAddress(): string;
}
```
- Deterministic RFC-6979 ECDSA signatures.
- Never exposes raw private key.
- Allows only allowlisted payload types (order, cancel, approval).

## Observability

### Prometheus Metrics (`:9090/metrics`)
| Metric | Type | Labels | Description |
|--------|------|--------|-------------|
| `polyroot_intents_total` | Counter | `mode`, `result` | Total intents processed. |
| `polyroot_fills_total` | Counter | `market`, `side` | Filled orders. |
| `polyroot_capital_reserved` | Gauge | `currency` | Capital currently reserved. |
| `polyroot_capital_available` | Gauge | `currency` | Capital available for new intents. |
| `polyroot_pnl_usd` | Gauge | `market` | Realized + unrealized PnL. |
| `polyroot_reality_gap_fill_rate` | Gauge | `market` | Shadow vs live fill rate gap (pp). |
| `polyroot_venue_mode` | Gauge | `venue`, `mode` | Current venue mode (enum). |
| `polyroot_executor_latency_ms` | Histogram | `operation` | End-to-end latency per operation. |

### Health Checks (`:8080/health`, `:8080/ready`)
```json
{
  "status": "healthy",
  "checks": {
    "database": "ok",
    "rpc": "ok",
    "venue": "ok",
    "signer": "ok"
  },
  "timestamp": "2026-01-15T10:30:00Z"
}
```

### Structured Logging
All logs are JSON with fields:
```json
{
  "timestamp": "2026-01-15T10:30:00.123Z",
  "level": "info",
  "component": "executor",
  "message": "Order submitted",
  "intentId": "abc123",
  "marketId": "mkt_0x123",
  "size": 1000000
}
```
Secrets (private keys, tokens) are automatically redacted.

## Deployment Modes

### Development (`npm run dev`)
- Runs gateway + executor in single process.
- Hot reload via `tsx` watch mode.
- PAPER mode by default.

### Production (Docker Compose)
```yaml
# docker-compose.prod.yml
services:
  gateway:
    image: polyroot/gateway:latest
    ports: ["3000:3000", "8080:8080", "9090:9090"]
    env_file: .env
    depends_on: [postgres, redis]
  
  executor:
    image: polyroot/executor:latest
    env_file: .env
    depends_on: [gateway]
  
  postgres:
    image: postgres:16-alpine
    volumes: [postgres-data:/var/lib/postgresql/data]
    environment:
      POSTGRES_DB: polyroot
      POSTGRES_USER: polyroot
      POSTGRES_PASSWORD: ${DB_PASSWORD}
  
  redis:
    image: redis:7-alpine
    volumes: [redis-data:/data]
```

### Kubernetes (Helm)
Helm chart available in `deploy/helm/polyroot` with values for:
- Replica counts, resource limits.
- Ingress + TLS termination.
- Prometheus ServiceMonitor.
- Secret management via ExternalSecrets.

## Error Taxonomy

All errors follow a structured schema:

```typescript
interface PolyrootError {
  code: string;           // Stable error code (e.g., "INSUFFICIENT_CAPITAL")
  message: string;        // Human-readable description
  details?: Record<string, unknown>;
  retryable: boolean;     // Whether client may retry
  severity: "WARN" | "ERROR" | "CRITICAL";
}
```

### Common Error Codes

| Code | HTTP | Retryable | Description |
|------|------|-----------|-------------|
| `INVALID_INTENT` | 400 | No | Intent failed validation. |
| `INSUFFICIENT_CAPITAL` | 400 | No | Reserved capital exhausted. |
| `VENUE_UNAVAILABLE` | 503 | Yes | Venue adapter reports UNAVAILABLE. |
| `VENUE_MODE_FORBIDS` | 409 | No | Current venue mode forbids action. |
| `SIGNER_UNAVAILABLE` | 503 | Yes | CryptoSigner not ready. |
| `PERMIT_EXPIRED` | 409 | No | Reservation permit expired. |
| `LEASE_EPOCH_MISMATCH` | 409 | No | Executor lease epoch stale. |
| `REALITY_GAP_EXCEEDED` | 409 | No | SHADOW→MICRO promotion blocked. |
| `AUTONOMY_CHARTER_REQUIRED` | 403 | No | LIVE mode requires charter. |
| `RATE_LIMIT_EXCEEDED` | 429 | Yes | API rate limit exceeded. |

### Venue Error Mapping
Venue-specific errors are normalized:
- `429` / queue-delay → `RETRYABLE`
- `401` / `403` → `AUTH_FAILURE`
- `5xx` unknown → `RECONCILE_REQUIRED`
- `FAK/IOC no-match` → `ZERO_FILL_TERMINAL` (not retryable)

## Integration Examples

### Submitting an Intent (Node.js)
```typescript
import fetch from "node-fetch";

const INTENT: TradeIntent = {
  marketId: "mkt_0xabc123",
  outcomeId: "yes",
  side: "BUY",
  size: 500000,      // 0.5 USDC
  maxPrice: 650000,  // 0.65 probability
  orderType: "LIMIT",
  meta: { strategy: "evidence_directional_v2" }
};

const response = await fetch("http://localhost:3000/intents", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": `Bearer ${process.env.GATEWAY_API_TOKEN}`
  },
  body: JSON.stringify(INTENT)
});

const result = await response.json();
console.log("Intent submitted:", result.intentId);
```

### Checking Readiness for Promotion
```bash
curl -H "Authorization: Bearer $TOKEN" http://localhost:3000/runtime/status | jq '.promotionReady'
```
